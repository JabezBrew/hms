# Stock transfer requests

Rust requests use one explicitly selected active item, source and destination, a safe whole positive quantity and the exact raw unit the operator reviewed. A fresh item read confirms that basis before dispatch; the adapter never truncates a legacy multi-item array, substitutes a newly fetched unit or converts quantity. The backend rechecks exact source/unit and persists requested_unit transactionally. This creates a request, not physical movement or completion.

The existing transfer list purpose is broader than the create form and optional location-label lookup: any InventoryView, InventoryManage, PharmacyDispense or ControlledSubstanceManage permission; Inventory OR Pharmacy feature; current facility and demographics visibility. The Rust route and sidebar use that exact list availability without changing inferred roles or shared authorization. The form separately keeps its narrower inventory view/manage, demographics capability/visibility, Inventory feature and current writable network policy. Optional labels use the existing conservative catalog-read availability; a broader list-only reader does not call a forbidden location endpoint or reuse retained labels. Recorded UUID fallback remains available. No new ordinary-password or factor requirement is added to transfers.

The route wrapper checks list availability and existing network readiness before mounting read hooks. The two compatibility list hooks accept an optional opaque scope and hash filter values; unscoped/Django callers retain their original signatures and cache behavior. A scoped pre-mount/unmount boundary clears only those scope's transfer/location list caches. Read identity/error notifications recheck the current clock before retaining a changed list or form view. Current denial hides retained content; old owner responses cannot populate the new scope. None of these UI fields grants transport or server authority.

Rust desktop cells and mobile cards show the actual request UUID, item name, quantity, request status/time and recorded requested_unit. NULL legacy units stay unrecorded; no live item fetch backfills them. Location UUIDs remain visible, with optional explicitly current labels from the bounded scoped location page. No requester identity or legacy transfer number is invented. Rust rows have no navigation into the absent detail route. Pagination describes records on the current cursor page, without a fabricated global total. Django retains its legacy columns, actions and genuine count behavior.

An unkeyed transfer has no governed command UUID or original-receipt protocol. Unknown outcomes retain the existing write-review barrier and cannot automatically retry. A displayed current request is not asserted to prove an earlier unknown command. No new replay, receipt acknowledgment or lifecycle semantics are introduced here.

Host/transport controls use synthetic HTTP/data and real clock handling. Root separately owns actual backend/native checks and browser geometry/release acceptance.
